# Техническая документация Travel Planner

##概述
Travel Planner — это веб-приложение для генерации персонализированных планов путешествий с использованием искусственного интеллекта и базы знаний (RAG-технология).

## Что это за приложение

Это онлайн-сервис, который помогает людям планировать путешествия. Пользователь выбирает:
- Откуда летит (город вылета)
- Куда хочет поехать (страна назначения)  
- Даты поездки
- Бюджет

И приложение генерирует подробный план с шагами: как получить визу, купить билеты, забронировать отель, оформить страховку и т.д.

## Как это работает (простыми словами)

### Основной принцип работы

1. **Пользователь заполняет форму** — выбирает параметры поездки
2. **ИИ ищет релевантную информацию** в базе знаний (визовые режимы, правила въезда, советы)
3. **ИИ генерирует персонализированный план** с конкретными шагами и ссылками
4. **Пользователь отмечает выполненные шаги** — видит прогресс

### Технологии "под капотом"

#### Фронтенд (то, что видит пользователь)
- **Next.js 16** — современный фреймворк для веб-приложений
- **React 19** — библиотека для создания интерфейса
- **Tailwind CSS** — стилизация (красивый дизайн)
- **TypeScript** — типизация для надёжности кода

#### Бэкенд (серверная часть)
- **API Routes** — обработка запросов на сервере Next.js
- **Anthropic API (через z.ai)** — генерация планов с помощью ИИ
- **Supabase** — база данных для хранения контента
- **Local Embeddings** — локальная обработка текста без внешних API

#### База знаний (RAG)
- **PostgreSQL + pgvector** — база данных с поддержкой векторов
- **@xenova/transformers** — локальная модель эмбеддингов (работает на вашем сервере)
- **Own documents** — ваши знания о путешествиях (визы, правила, советы)

## Подходы и архитектурные решения

### 1. RAG (Retrieval-Augmented Generation)

**Что это:** Комбинация поиска по базе знаний и генерации ИИ.

**Как работает:**
1. Пользовательский запрос конвертируется в вектор (embedding)
2. В базе данных ищутся похожие документы
3. Найденные документы добавляются в контекст ИИ
4. ИИ генерирует ответ на основе этих знаний

**Плюсы:**
- ✅ Использует актуальную информацию из базы знаний
- ✅ Можно легко обновлять знания без переобучения модели
- ✅ Галлюцинации ИИ минимизированы (опирается на факты)
- ✅ Прозрачность — можно проверить источники

**Минусы:**
- ❌ Сложность настройки (threshold, количество документов)
- ❌ Зависимость от качества базы знаний
- ❌ Требует обслуживания (индексация, обновление)

### 2. Локальные эмбеддинги (Local Embeddings)

**Что это:** Модель для конвертации текста в векторы работает локально, без внешних API.

**Как работает:**
- Используется библиотека @xenova/transformers
- Модель: paraphrase-multilingual-MiniLM-L12-v2
- Работает в среде Node.js через ONNX Runtime

**Плюсы:**
- ✅ Полностью бесплатно (нет затрат на API эмбеддингов)
- ✅ Privacy-first (данные не уходят на внешние серверы)
- ✅ Работает с русским языком (мультиязычная модель)
- ✅ Нет rate limits

**Минусы:**
- ❌ Первый запуск медленный (~30 секунд загрузка модели)
- ❌ Требует больше памяти сервера
- ❌ Сложность настройки в serverless среде (Vercel)

### 3. Serverless-архитектура (Vercel)

**Что это:** Приложение работает на serverless-функциях Vercel.

**Как работает:**
- API-маршруты Next.js разворачиваются как serverless-функции
- Бесконечное масштабирование
- Автоматическое масштабирование под нагрузкой

**Плюсы:**
- ✅ Бесплатный tier для small apps
- ✅ Автоматическое масштабирование
- ✅ Простота деплоя (git push → deploy)
- ✅ CDN для быстрой доставки контента

**Минусы:**
- ❌ Ограничения по времени выполнения (60 секунд)
- ❌ Холодный старт (первый запрос медленнее)
- ❌ Ограничения памяти и дискового пространства
- ❌ Сложность работы с нативными модулями (onnxruntime)

### 4. Graceful Fallback

**Что это:** Если база знаний недоступна, приложение работает без неё.

**Как работает:**
- Проверка подключения к Supabase
- При ошибке RAG — fallback на общие знания модели
- Пользователь видит бейдж "База знаний не использована"

**Плюсы:**
- ✅ Приложение всегда работает
- ✅ Пользователь видит прозрачный статус
- ✅ Нет полных отказов в сервисе

**Минусы:**
- ❌ Без базы знаний возможны галлюцинации ИИ
- ❌ Менее качественные планы без специфической информации

### 5. Админ-панель в браузере

**Что это:** Управление базой знаний через веб-интерфейс без терминала.

**Как работает:**
- CRUD-операции над документами (создание, чтение, редактирование, удаление)
- Переиндексация одним кликом
- Статусы: черновик/опубликовано, embeddings устарели/актуальны

**Плюсы:**
- ✅ Не нужен доступ к Supabase Dashboard
- ✅ Не нужны терминальные команды
- ✅ Визуальное отображение статусов
- ✅ Простота для не-технических пользователей

**Минусы:**
- ❌ Ограничения по массовым операциям (тысячи документов)
- ❌ Serverless-таймауты на больших переиндексациях
- ❌ Не заменяет полностью Supabase Dashboard

### 6. Response Caching

**Что это:** Кэширование идентичных запросов для избежания повторных вызовов ИИ.

**Как работает:**
- Ключ кэша на основе параметров поездки
- Хранение в памяти (per-instance)
- Time-based expiry (1 час)

**Плюсы:**
- ✅ Экономия затрат на API ИИ
- ✅ Быстрый ответ на повторные запросы
- ✅ Снижение нагрузки на сервер

**Минусы:**
- ❌ Не работает на Vercel (каждый instance имеет свой кэш)
- ❌ При cold start кэш очищается
- ❌ Может вернуть устаревший план (если база знаний обновилась)

### 7. Rate Limiting

**Что это:** Защита от злоупотреблений публичным API.

**Как работает:**
- In-memory счётчик запросов по IP
- 10 запросов в час на IP
- HTTP 429 при превышении

**Плюсы:**
- ✅ Защита от abuse
- ✅ Предотвращение перерасхода API
- ✅ Простота реализации

**Минусы:**
- ❌ In-memory — не работает на Vercel (каждый instance свой счётчик)
- ❌ Легко обойти через прокси/VPN
- ❌ Блокирует легитимных пользователей при превышении

## Структура базы данных

### Таблица raw_documents (сырые документы)

```sql
CREATE TABLE raw_documents (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL UNIQUE,        -- Заголовок документа
  category TEXT NOT NULL,            -- Категория (visa, insurance, telecom, ...)
  content TEXT NOT NULL,             -- Полный текст документа
  is_published BOOLEAN DEFAULT true, -- Опубликовано или черновик
  country TEXT NOT NULL,             -- Страна (Вьетнам, Таиланд, ...)
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

**Назначение:** Хранение исходного контента базы знаний, который редактируется в админ-панели.

### Таблица documents (чанки с эмбеддингами)

```sql
CREATE TABLE documents (
  id SERIAL PRIMARY KEY,
  content TEXT NOT NULL,            -- Текст чанка
  embedding vector(384),            -- Вектор (эмбеддинг)
  source_file TEXT,                 -- Имя исходного файла
  country TEXT,                     -- Страна
  raw_document_id INTEGER,          -- Ссылка на raw_documents
  created_at TIMESTAMPTZ DEFAULT NOW(),
  last_indexed_at TIMESTAMPTZ       -- Время последней индексации
);
```

**Назначение:** Хранение чанков текста с векторами для семантического поиска.

### RPC-функция match_documents

```sql
CREATE FUNCTION match_documents(
  query_embedding vector(384),
  match_threshold float DEFAULT 0.4,
  match_count int DEFAULT 5,
  filter_country text DEFAULT NULL
)
RETURNS TABLE (
  id integer,
  content text,
  source_file text,
  similarity float
);
```

**Назначение:** Поиск релевантных чанков по вектору с фильтрацией по стране и опубликованным документам.

## Экосистема и интеграции

- ❌ Ограничения бесплатного tier
- ❌ Сложность миграции при росте
- ❌ Зависимость от стороннего сервиса

### 2. Anthropic API (через z.ai)

**Что это:** API для генерации текста с помощью ИИ.

**Использование:**
- Генерация планов путешествий
- Модель: glm-4.6 (аналог Claude)

- ✅ Высокое качество генерации
- ✅ Поддержка русского языка
- ✅ Предсказуемое поведение

**Минусы:**

- ❌ Rate limits
- ❌ Зависимость от внешнего сервиса
- ❌ Возможные галлюцинации (без RAG)

**Что это:** JavaScript-версия библиотеки Transformers для локальных ML-моделей.

**Использование:**
- Генерация эмбеддингов на сервере

**Плюсы:**
- ✅ Работает локально (без внешних API)
- ✅ Поддержка русского языка
- ✅ Бесплатно
- ✅ Privacy-first

**Минусы:**
- ❌ Первый запуск медленный
- ❌ Потребление памяти
- ❌ Сложность настройки в serverless

## Безопасность

### 1. Аутентификация админ-панели

**Что это:** Простой пароль для доступа к управлению контентом.

**Как работает:**
- Пароль из переменной окружения ADMIN_PASSWORD
- Передаётся в заголовке x-admin-password
- Проверка на сервере в API-маршрутах

**Плюсы:**
- ✅ Простота реализации
- ✅ Не требует сложной инфраструктуры
- ✅ Достаточно для small apps

**Минусы:**
- ❌ Не безопасно для production (один пароль на всех)
- ❌ Нет автоматического выхода (timeout)
- ❌ XSS-угрозы (localStorage)

### 2. Валидация входных данных

**Что это:** Проверка данных от пользователя перед обработкой.

**Как работает:**
- Zod-схемы для валидации
- Проверка типов, диапазонов, форматов
- Подробные сообщения об ошибках

**Плюсы:**
- ✅ Защита от некорректных данных
- ✅ Понятные сообщения об ошибках
- ✅ Type safety

**Минусы:**
- ❌ Требует описания схем
- ❌ Не защищает от намеренного злоупотребления

### 3. Security Headers

**Что это:** HTTP-заголовки для защиты от XSS и других атак.

**Как работает:**
- X-Frame-Options: DENY
- X-Content-Type-Options: nosniff
- Referrer-Policy: strict-origin-when-cross-origin
- Permissions-Policy: ограничение camera/microphone/geolocation

**Плюсы:**
- ✅ Стандартная защита
- ✅ Простота включения
- ✅ Встроена в Next.js

**Минусы:**
- ❌ Не защищает от всех атак
- ❌ Требует дополнительной защиты

## Производительность и масштабируемость

### 1. Оптимизации в коде

**Lazy loading:**
- Эмбеддинги подгружаются только при RAG-запросе

**Serverless:**
- 60 секунд на выполнение функции
- Холодный старт (~1-2 секунды)
- Память: ~1GB на Vercel free tier

- 500MB на Supabase free tier

- Медленный запрос при большом количестве документов без индекса

- Первый запрос ~30 секунд (загрузка модели)

## 🚨 КРИТИЧЕСКИЕ ПРОБЛЕМЫ И РЕШЕНИЯ

### Проблема: "Insufficient balance or no resource package"

**Симптом:** Ошибка при генерации плана с сообщением:
```
Ошибка API: недостаточно баланса или нет активного тарифного плана
```

**Причина:** На API ключе z.ai закончился баланс или нет активного тарифного плана.

**Решение:**
1. Зайдите в личный кабинет https://z.ai
2. Пополните баланс или активируйте тарифный план
3. Проверьте, что API ключ `9d0a947f238b466fbac22db7291ce5b8.Pm9C7HqYsPULeGmR` активен

**Текущие настройки:**
```env
ANTHROPIC_API_KEY=9d0a947f238b466fbac22db7291ce5b8.Pm9C7HqYsPULeGmR
ANTHROPIC_BASE_URL=https://api.z.ai/api/anthropic
ANTHROPIC_MODEL=glm-5.2
```

### Проблема: Кириллические символы искажаются в curl (Windows)

**Симптом:** Ошибка валидации "Invalid input" при отправке запроса с кириллицей через cmd.

**Причина:** Windows консоль использует кодировку, отличную от UTF-8.

**Решение:** Используйте файл с правильной кодировкой UTF-8:
```bash
# Создайте файл test_request.json с UTF-8 кодировкой
curl -X POST http://localhost:3006/api/generate-plan \
  -H "Content-Type: application/json; charset=utf-8" \
  --data-binary @test_request.json
```

### Проблема: "Cannot read properties of undefined (reading 'map')"

**Симптом:** Внутренняя ошибка сервера при валидации.

**Причина:** Некорректная обработка массива ошибок в Zod.

**Статус:** ✅ ИСПРАВЛЕНО — добавлена защитная проверка в `validationErrorResponse()`

## Траблшутинг (решение проблем)

### 1. Проблема: Медленная загрузка модели

**Симптом:** Первый запрос к API занимает ~30 секунд.

**Решение:**
- Это нормально — первый запуск загружает ONNX-модель
- Последующие запросы быстрые (~50-100ms)
- Можно предзагрузить модель при старте сервера

### 2. Проблема: RAG не находит документы

**Симптом:** Бейдж "База знаний не использована".

**Возможные причины:**
- Не выполнены SQL-миграции (init-db.sql, migrate-docs-to-ui.sql)
- Документы не опубликованы (is_published = false)
- Threshold слишком строгий (match_threshold = 0.4)
- Нет документов для выбранной страны

**Решение:**
- Проверьте выполненные миграции в Supabase SQL Editor
- Опубликуйте документы в админ-панели
- Попробуйте снизить threshold
- Добавьте документы для нужной страны

### 3. Проблема: Serverless timeout на Vercel

**Симптом:** 504 Gateway Timeout при генерации плана.

**Возможные причины:**
- Первый запрос (загрузка модели + холодный старт)
- Большое количество документов в RAG-контексте
- Медленный ответ от Anthropic API

**Решение:**
- Увеличить maxDuration (сейчас 60 секунд)
- Предзагрузить модель (warmup запросы)
- Ограничить количество документов в контексте (MAX_DOCS = 5)
- Оптимизировать промпт (меньше токенов)

### 4. Проблема: Галлюцинации ИИ

**Симптом:** План содержит информацию, которой нет в базе знаний.

**Возможные причины:**
- RAG не сработал (fallback на общие знания)
- Промпт не строго запрещает использовать общие знания
- Контекст слишком маленький

**Решение:**
- Проверить статус RAG (_usedRag, _ragReason в ответе)
- Усилить промпт (строже запретить общие знания)
- Увеличить контекст (больше документов)

## Заключение

Travel Planner — это современное веб-приложение, использующее передовые технологии ИИ и баз данных для создания персонализированных планов путешествий. Архитектура приложения балансирует между качеством, стоимостью и сложностью поддержки.

### Ключевые преимущества

1. **RAG-подход** — использование актуальной базы знаний минимизирует галлюцинации
2. **Local embeddings** — отсутствие затрат на API эмбеддингов
3. **Graceful fallback** — приложение всегда работает
4. **Админ-панель** — простое управление контентом без терминала
5. **Serverless** — автоматическое масштабирование

### Компромиссы

1. **Сложность** — RAG, embeddings, serverless требуют экспертизы
2. **Производительность** — холодный старт, ограничение по времени
3. **Затраты** — Anthropic API, Supabase (при росте)
4. **Безопасность** — простая парольная защита админки
